## 4. Findings, ranked by score impact

1. **Sheets are opaque, not glass** — dev-fixture-06, -10, -14, -20 (and jvm-11/12/15 by manifest). `apps/android/mobile/src/main/kotlin/com/raydocs/tono/mobile/ui/DetailsSheet.kt:56`, `LinesSheet.kt:~46`, `ConsentSheet.kt:~47` set `containerColor = TonoColors.Smoke` with the comment "opaque: device renders showed home text through a 97% sheet". That problem was alpha without blur; `Glass.kt` already blurs its own slice of the BackdropHost recording, so text behind becomes a soft glow. Fix: pass `containerColor = Color.Transparent` and wrap the sheet content in `Glass(shape, tintAlpha ≈ 0.80, blur = 26.dp)`; keep the scrim. Verify with the u4 stripe test applied to the sheet slice. Raises D4 (+2 to +3).
2. **Mid-transition flash: label-less warm capsule and ghosted headline** — dev-motion-frames.png frame 261 (4176 ms), jvm-motion-connect-cycle-reduced-frames.png frame 48 (2400 ms). `HomeScreen.kt:291-330` (`labelColor` tween 220 ms; warm capsule "fades over the glass"). Fix: drive label alpha, fill and headline crossfade from one transition progress so the label is never at alpha 0 while the fill is warm; under reduced motion snap headline and sun (no crossfade/position tween), keep only colour. Raises D5 (+1 to +2).
3. **Throughput caption wraps with a dangling separator at 200 %** — dev-fixture-13, local-16c ("↓ 2.34 MB/s ·" / "↑ 81 KB/s"). `HomeScreen.kt:412` formats `R.string.speed_line` from two `Format.rate()` strings (which already use NBSP internally, `Format.kt:27-28`). Fix: make the " · " in `speed_line` non-breaking, or switch to two intentional lines when `fontScale > 1.3`. Also check the 200 % Details rows (dev-fixture-14: arrow hangs beside a two-line "Home broadband"): align the arrow to the first line. Raises D6 (+1).
4. **Connecting sweep colour** — dev-fixture-02, dev-motion-frames frames 78/104. The progress fill lerps toward a muddy tan/brown. `HomeScreen.kt:296-330`. Fix: sweep with `SunMid` at ~35 % alpha over the glass instead of a lerp toward Smoke; keep label contrast. Raises D3 (+1).
5. **Sign-in error placement and colour** — dev-real-02, jvm-02. "Enter a valid email." appears under the Send button in saturated red. `SignInScreen.kt` (error text after the button; string `signin_error_INVALID_EMAIL` at `res/values/strings.xml:73`). Fix: `OutlinedTextField(isError, supportingText)` so the message sits under the field, in an AA-lightened Ember rather than pure red. Raises D1/D3 (+1).
6. **Home headline peeks, clipped, above the Lines sheet** — dev-fixture-10 ("Partly working" cut by the sheet edge). `LinesSheet.kt` scrim 0.55. Fix: fade the Home headline to alpha 0 while any sheet is open (the wordmark already dims), or raise the scrim. Raises D1 (+0.5).
7. **Notification action during Connecting is "Disconnect"; app says "Cancel"** — dev-fixture-18. `surface/SurfaceCopy.kt:17` maps BUSY to `state_connecting`; the action label is fixed. Fix: BUSY + CONNECTING → "Cancel". Raises D1 (+0.5).
8. **No light appearance** — dev-real-11 vs dev-real-12 identical (theme-report.txt). If dark-only is the brand decision, record it; otherwise a light Horizon (day sea) would lift D6. Not penalised beyond D6's current 8.
9. **Settings amber warning block** — dev-fixture-11/-15. Three amber lines plus a button. Fix: one neutral line ("Not always-on. Apps go direct if Tono stops.") with the button; keep amber for the dot only. D1/D3 (+0.5).
10. **Not scored, verify:** jvm-07/08/09/10 show a faint ghost "⚙ 详情" pill at the top-right. No emulator capture shows it. Most likely Robolectric NATIVE drawing the BackdropHost recording with a wrong origin in `Glass.kt:86-91` (`drawLayer` with `translate(backdrop.origin - origin)`); if it ever appears on a device it is a D3 defect. One Robolectric assertion on the top-right region would settle it.
11. **Not scored, verify:** CI attempt 1 `t3` did not see a Connecting state before Connected (`LocalTunnelDeviceTest.kt:686`); retry did. If the real engine connects faster than the sun's rise, the user sees a jump. Consider a minimum visible dwell for CONNECTING (fixture already shows 400 ms PREPARING → 992 ms CONNECTING) and a test that asserts it with the real engine.

## 2026-10-02 · Windows：连接期间要不要放行局域网，放行哪些

- Status: provisional. 「放行局域网」是所有者的决定（2026-10-02，会话内）；具体放行哪些地址、端口和方向是 agent 按较严一侧选的。
- Chosen: 只在 `Locked` 且有隧道 LUID 时渲染，非持久。出站放行 `10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`fe80::/10`、`fc00::/7`，发现用的 `224.0.0.0/24`、`255.255.255.255`、`ff02::/16`，以及 SSDP 的 `239.255.255.250` UDP 1900；入站只放行来自上述单播段的对端。远端端口 53 和 853 不在放行范围内。核心进程（staged core）到这些地址另加一条阻断。不选：按网卡当前前缀放行（TunnelCrack LocalNet：恶意网络可以把公网段宣告成「本地」）；放行运营商 NAT `100.64/10`（macOS 也不放）；放行整个 `239/8`；做成用户开关（这一版不加设置项）；在放行之上再加一条 53 端口阻断（规则 E 的注释记录过：独立的 53 端口阻断在真机上打断过 Windows 的解析路径，所以改成放行规则本身不覆盖这两个端口，发往这两个端口的流量仍由改动前的规则决定）。
- Why stricter: `Bootstrap`、`Blocked`、没有 LUID 的 `Locked` 都不渲染这些规则，没有隧道时局域网和以前一样不可达。地址表是静态的不可路由段。局域网 DNS（53/853）不放行，系统解析器发给路由器的查询和以前一样被兜底阻断。核心进程到局域网被阻断，规则 H（WeChat 的 DIRECT）仍只到公网单播。入站只对局域网对端开放，Windows 防火墙在自己的 sublayer 里照常裁决。多放行的是：连接期间任何进程可以直连同网段的私网和链路本地地址（53/853 除外），局域网对端可以向本机发起连接。和 macOS 的 `tono-lan`、`tono-linklocal`、`tono-ssdp` 同一形状（[决策 045](045-2026-10-02-macos-lan-discovery-pf.md)）。
- Applied in: [#1355](https://github.com/raydocs/tono/pull/1355)。

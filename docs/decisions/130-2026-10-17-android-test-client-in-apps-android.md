## 2026-10-17 · How does the Android sing-box test client enter raydocs/tono, and how are test builds delivered?

- Status: provisional
- Chosen: `apps/android` is a self-contained Gradle build mirrored from rw8/Tono-droid by `scripts/export-android-monorepo.sh` (mobile + routing modules, sing-box pin, routing scripts only; no Mihomo/internal-core artifacts, keys or binaries). Test APKs are debug-signed with the CI runner's ephemeral key and delivered only as GitHub Actions artifacts (90-day retention); the release variant stays disabled. Rejected: a new repository, a GitHub Release, a store listing, or committing `libbox.aar` (CI rebuilds it from the pinned source and Gradle refuses any other SHA-256).
- Why stricter: nothing is published or promoted; no desktop feed, package, Worker or existing asset changes; `android-ci.yml` is not wired into `ci-gate`, so the required check and merge queue are unchanged. Routing stays fail-closed (AI and the named Home list → cloud → Home, video → cloud, everything else DIRECT; a matched route that fails is refused). Tokens and the cached catalog stay AES-GCM encrypted with a non-exportable Android Keystore key and excluded from backup. The internal-test gate is a delivery choice, not a claim that GPL-3.0-or-later forbids release; any store or public release needs an owner decision (including sing-box's name clause).
- Applied in: branch `feat/android-singbox-horizon` (draft PR, not for merge during the G4 freeze); ops plan §P2 "Android / iOS 客户端". Decision 129 is taken by the iOS draft (#1672).

## 2026-11-27 · Hysteria 2 Brutal stays default BBR with per-node opt-in down-mbps

- Status: owner
- Chosen: leave `up_mbps` and `down_mbps` unset by default on `sing-box` Hysteria 2 outbounds (so both directions use adaptive QUIC + BBR via `sing-quic`), admit an optional bounded integer `down-mbps` (`10..=500`) on ` · hy2` catalog blocks for nodes with lossy return paths, and add `manage-tono-hy2-node.sh set-bandwidth` (`ignoreClientBandwidth` / `up` / `down`) so server-side Brutal can be switched off at once per node. Client `up_mbps` is never admitted or emitted. Rejected: hardcoding global `up_mbps: 50 / down_mbps: 200` on every desktop HY2 outbound, which would overshoot 10–40 Mbps uplinks and cellular hotspots under Brutal fixed-rate pacing.
- Why stricter: default behavior widens zero congestion surface; `down-mbps` is bounded (`10..=500`), restricted to block-style YAML on ` · hy2` entries only (ignored by legacy `0.0.88` clients), never sets `up_mbps`, and leaves Helper protocol (`HelperProtocolVersion`) and kill-switch boundaries untouched.
- Applied in: `services/control-plane/src/catalog-yaml.ts`, `apps/windows/crates/tono-core/src/{node.rs,sing_box/runtime.rs}`, `apps/macos/Tono/{Models/ProxyNode.swift,Services/ConfigParser.swift,Core/Configuration/ConfigPipeline+Nodes.swift,Core/Configuration/ConfigPipeline+SingBoxProduct.swift}`, and `tooling/scripts/remote/manage-tono-hy2-node.sh`.

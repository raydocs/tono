# Tono 运维后台 · 五部门并行作战计划（2026-09-10）

角色：总监 = 本会话（Fable，spookfish 工作树，`ops/platform` 的唯一合并者与部署者）。五个部门经理 = 五个独立的 Fable 会话，每个用 ultracode 跑 workflow 管自己的 subagent（Grok 做机械实现、Opus 做页面与合同、Fable 自己做设计与审查）。经理不直接碰 `ops/platform` 和 `main`。

一句话分工原则：**按产品面切，不按技术层切**。每个部门同时拥有自己那一面的 Worker 代码、控制台页面、夹具、测试和文档，这样部门内部能独立闭环；跨部门只通过「合同」和「共享文件协议」交接。

## 0. 全局规则（五个经理都要背下来）

1. **分支树**：`main`（生产）← `ops/platform`（集成，只有总监合并）← `dept/<部门>`（部门集成，只有经理合并）← `dept/<部门>/<任务>`（subagent 工作树）。每个部门自己的工作树在 `/Users/ruirui/orca/workspaces/tono/dept-<部门>/`，subagent 工作树在 `dept-<部门>-<任务>/`。`node_modules` 一律软链接（control-plane 指 `/Users/ruirui/Downloads/GitHub/tono/services/control-plane/node_modules`，ops-console 指 `/Users/ruirui/orca/workspaces/tono/ops-console/services/ops-console/node_modules`）。
2. **文件所有权**（§2 的表）是硬边界。不属于你的文件只能做「加一行」式的追加，并在 PR 说明里单列「触碰了别人的文件」。共享文件见 §3 协议。
3. **合同先行**：任何 DTO / 路由 / 词表改动，先在 `services/control-plane/src/ops/contract/*` 和 `docs/ops/api-contract.md` 里改，作为一个独立的小 PR（`contract:` 前缀）发给总监；总监半小时内合到 `ops/platform`，所有部门 rebase 后才开始实现。避免两个部门对同一个 DTO 各写一版。
4. **迁移号段**：迁移只增不改，每个部门今天领一个号段，用不完的留空：A 0057–0059，B 0060–0062，C 0063–0065，D 0066–0068，E 0069–0071。`migrations/README.md` 的高水位由总监在合并时改。
5. **验证命令不变**：Worker `npm run typecheck && npm run check:contract && npm run check:budgets && npm test`；控制台 `npm run typecheck && npm run lint && npm test && npx playwright test --workers=4 && npm run build && node scripts/check-budgets.mjs`。Playwright 前 `pkill -f "mode fixtures"`，端口按部门：A 5310、B 5320、C 5330、D 5340、E 5350（subagent 在此基础上 +1、+2…）。
6. **提交尾注**：`Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`（Opus 写的用 Opus 5），`Claude-Session:` 用各自会话链接。`.grok/` 不进提交。密钥只走 `wrangler secret put`，运营者邮箱不进夹具与种子，`secretRef` 只允许 `ALERT_*`。
7. **交付节奏**：每天两次集成，12:00 和 18:00（Asia/Shanghai）前经理把 `dept/<部门> → ops/platform` 的 PR 开好（CI 绿、说明里有原始验证输出、触碰共享文件清单、迁移号）。总监 13:00 与 19:00 按固定顺序合并（A → B → C → D → E），全量跑一遍，备份，部署，浏览器验，写 runbook。冲突由**后合并的部门**解决。
8. **沟通**：经理会话用 `ListAgents` 找到总监会话（spookfish），用 `SendMessage` 发状态；格式固定：`[部门] 任务 · 状态(进行中/待审/PR#) · 阻塞(无/内容) · 触碰共享文件(无/清单) · 迁移号`。总监的指令也用同一渠道回。人（老板）只看总监的汇总。
9. **ultracode 用法**（经理自己的 workflow 模板见 §5）：每个任务 = 理解 → 实现 → 3 个反驳者对抗审查 → 修 → 验证。实现型 agent 用 `agentType: 'grok'`（机械）或 `model: 'opus'`（页面与合同）；反驳者与评审用 Fable（默认模型）。经理**必须亲自读 diff**再合并，不能只看 agent 的报告。
10. **不做**：自动下架 / 自动换节点、OpenAPI 生成、换数据库、给 `/ops/` 加功能、把商家登录信息放进库、Pages 部署、新域名。

## 5. 经理的 ultracode 模板（每个任务一个 workflow）

```js
export const meta = {
  name: 'dept-task',
  description: 'understand → implement → adversarial review → fix → verify',
  phases: [{ title: 'Understand' }, { title: 'Implement' }, { title: 'Refute' }, { title: 'Fix' }, { title: 'Verify' }],
}
const { brief, worktree, kind } = args   // kind: 'grok' | 'opus'
phase('Understand')
const map = await agent(`Read ${brief} and the files it names under ${worktree}. Return: files to touch, files NOT to touch (ownership table in docs/ops/org-plan-2026-09-10.md §2), contract fields needed, tests to add.`, { schema: MAP })
phase('Implement')
const impl = kind === 'grok'
  ? await agent(`Run the brief ${brief} in ${worktree}. No git state changes. Report per item with raw verification.`, { agentType: 'grok', label: 'implement' })
  : await agent(`Implement the brief ${brief} in ${worktree} …`, { model: 'opus', label: 'implement' })
phase('Refute')
const votes = await parallel(['correctness', 'contract-and-ownership', 'tests-actually-prove-it'].map(lens => () =>
  agent(`Lens: ${lens}. Read the diff in ${worktree} (git diff) against ${brief}. Try to refute that it is correct and complete. Default refuted=true if uncertain.`, { schema: VERDICT, label: `refute:${lens}` })))
const problems = votes.filter(Boolean).filter(v => v.refuted)
phase('Fix')
if (problems.length) await agent(`Fix these in ${worktree}: ${JSON.stringify(problems)}. Add the narrowest test for each.`, { agentType: kind === 'grok' ? 'grok' : undefined, model: kind === 'opus' ? 'opus' : undefined })
phase('Verify')
return await agent(`In ${worktree} run the full verification for the touched package(s) and paste raw output. Do not edit code.`, { schema: VERIFY, effort: 'low' })
```

经理在 workflow 之外要做的：写 brief（目标、路径、约束、验证、报告格式）、亲自读 diff、合并到 `dept/*`、开 PR、发状态消息。

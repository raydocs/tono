### 写入安全语义

- 一个批次未收起前不能再发起新批次；同一个入口、重试回调均有 busy 防重入。
- 读取失败可重读，明确的请求拒绝可重试。超时、断网、5xx、会话跳转、
  成功响应解析失败均按“结果未知”处理，不推定服务端未写入。
- 已有设备回执的项不会再下发，包括回执报失败/过期的项。运营者先查看客户，
  再决定是否另发新动作。不用“最近一条回执”冒充本次结果。
- 续期的目标日期在首次确认时确定；重试仍用同一目标，不再加 30 天。
  写前读到的到期日若与选择时不同则不写；写后必须读回相同日期才说“已核对”。
- **写前读取不是原子 CAS**：读取与 PATCH 之间仍可能被其他运营者修改。
  本轮没有改 Worker，因此不能声称消除了多运营者竞态。
- 批次只放标签页内存，不落 localStorage；客户页卸载不丢运行结果。
  刷新/关闭标签页会丢内存记录，且不会自动续写。未知结果仍需人工核对。

## 下一步值得添加什么（提案，不代表已实现/已授权后端扩展）

1. **并发变更保护**：对客户续期等写入增加版本/原值前提，服务端原子拒绝过期编辑；
   UI 展示“你看到的 / 当前的 / 打算写入的”，不自动覆盖。优先于更多写按钮。
2. **批量影响预览**：确认前列出最终设备清单、不可操作原因和逐客户新旧日期，
   让运营者先剔除不该处理的对象；不增加新的金额计算规则。
3. **可恢复的操作回执**：服务端幂等键 + 批次查询，用于“服务端已写但响应丢失”
   和刷新页面后的恢复。必须合同先行，不能用前端自动重试冒充幂等。
4. **脱敏交接摘要**：复用现有客户时间线、事故、跟进、回执，生成可复制的
   “已确认 / 已操作 / 待验证 / 下一次检查”摘要；尊重隐私开关，不默认导出原始日志。
5. **常用视图**：运营者保存“Windows 落后版本”“待回访”等筛选组合，
   明确保存范围与隐私；不是再做一套已有的全局搜索。
6. **变更后验证对照**：把本次动作前后的目录版本/故障证据/客户回话并排，
   复用已有跟进状态，区分“命令完成”与“客户真的恢复”，不自动关闭事故。

推荐顺序：先独立审查本批 → WF-4/5 的后端合同与规模证据 → 并发保护/影响预览。
不因为能加按钮就无限扩功能，不重新设计 Today/Shell/设置等已认可页面。

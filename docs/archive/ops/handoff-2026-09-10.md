## 0. 现状一句话与打分

`/ops2/` 已经是日常后台：事故、节点上下线、目录与分流发布、家宽库存、客户开通与处置、跟进、早报、账目都在里面；今天为止 9 次生产部署，迁移到 0055，Worker 743 个测试、控制台 260 个单测 + 305 个 Playwright 基线。它已经是「能用的产品」，但离「完整产品」还差一截：告警没接通真实通道、客户生命周期只覆盖了「已经能上报的人」、节点上架下架还是按钮而不是流程、客户端两端还没对齐、恢复演练刚开始做。

**总分：6.5 / 10（作为一个「完整产品」）。** 分项：

## 3. 缺口清单（产品经理视角，按优先级）

## 7. 接手方式（Handoff）

- **分支**：主开发分支 `ops/platform`（spookfish 工作树），每波从它开 `ops-waveN-x` 工作树（`git worktree add ../ops-waveN-x -b ops/waveN-x ops/platform`），`node_modules` 用符号链接（control-plane 指主检出，ops-console 指 `orca/workspaces/tono/ops-console`）。
- **brief**：都在会话 scratchpad `brief-waveN-x.md`；模板：目标、精确路径、约束（不改 git 状态、迁移只增、密钥只走 `wrangler secret put`、运营者邮箱不进夹具、`secretRef` 只允许 `ALERT_*`）、验证命令、报告格式。Grok 走 `grok` 子代理（返回早，用 `while kill -0 <pid>` 盯 `~/.claude/grok-runs/*.log`）；Opus 走 `Agent model=opus`。
- **审查**：Fable 读 diff，跑最窄检查，再全量；控制台 Playwright 要 `pkill -f "mode fixtures"` + 独立 `OPS_CONSOLE_PORT`。
- **验证命令**：Worker `npm run typecheck && npm run check:contract && npm run check:budgets && npm test`；控制台 `npm run typecheck && npm run lint && npm test && npx playwright test --workers=4 && npm run build && node scripts/check-budgets.mjs`。

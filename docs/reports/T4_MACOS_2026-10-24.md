## P1：IPC SIGPIPE

- `HelperManager.sendRequest` 为每个 Unix socket 设置并检查 `SO_NOSIGPIPE`；设置失败即返回传输错误。
- AppDelegate 启动时另行忽略 SIGPIPE。写入 EPIPE 沿既有 `socketFailed` 返回，不重放请求；
  `upgradeRequestMayHaveBeenDelivered` 仍把未写完请求归为未送达，避免把潜在副作用命令自动重放。
- 回归用本地 socket 在 connect 完成后同步 accept/close 对端，再调用真实 sendRequest；无 sleep。
  检查 socket 选项后，在具备保护时恢复 SIG_DFL，验证并非依赖 AppKit 的忽略信号才不退出。

## P1：root CLI break-glass

- 只有 `runEmergencyDisarm` / `runEmergencyResetLocked` 显式选择 `.rootEmergency`；
  `emergencyRelease` 与无账本 fallback 默认 `.runtime`，自动卸载复用路径不获得越权。
- root emergency manager 不执行启动重装阻断，禁止 arm；disarm 可以越过 strict/不可读意图，输出 stderr。
- manager 初始化与 disarm 均检查实际 euid。GUI SocketServer 没有选择 authority 的请求字段或入口，
  默认 runtime 即使运行于 root，也不能越过 strict。
- helper 协议版本 `4.52.64 → 4.52.65`：安装门只比较该版本，因此必须更新；不新增 IPC 字段。
- 锁忙时不写记录；损坏记录按既有规则重建并保留 historyLost；save 失败不伪报已保存。
  这些手动路径本来就在 restore-lock 保证外；不声称已排除其他进程之后重新 arm。

## T6 协作：429 与账户错误契约

只读 T6 `3205b5c76` 的 `docs/control-plane-error-contract.md`，没有修改控制面文件。
对应 [#1738](https://github.com/raydocs/tono/pull/1738)，T6 通知 head `429e23427`；其全量有两个旧 401 断言失败，不记全绿，也不沿用为本 PR 验证。
- 429 现在携带类型化 retry duration；URLSession、固定地址和 relay 路径都保留最终 HTTP head 的 Retry-After。
  整数秒有效时照用，缺失/格式错误时退避 60 秒；不重试或吞掉该 HTTP 交换。
- Outbox 将 429 保留，按 `failure` / `diagnostics` / `p0` 分开持久化 not-before。
  同桶后续报告等到期限，P0 不被普通诊断桶拖住。并发 drain 不再重发同一快照。
  立即 failure 上报同样遵守已经记下的期限；timeout 的既有去重规则不变。
- 新增 `PLAN_EXPIRED`、`QUOTA_EXHAUSTED`、`DEVICE_REAUTH_REQUIRED` 到 entitlement 分类，
  沿既有 suspended 流程保留登录/令牌/设备配置，撤下不可再使用的出口目录与网络凭据。
  到期/超额提示续费或联系家人；设备需重新验证的提示不会自动恢复网络授权。
- UI 文案只增加四条英/简中文翻译；未覆盖 #1724 的既有改动，也未改 T7 更新文案。

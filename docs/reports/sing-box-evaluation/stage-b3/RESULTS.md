# B3：长 SSE 的 gVisor CPU 优势复现；不构成迁移结论

**同一 sing-box 二进制中，gVisor 在本次小事件长 SSE 的 CPU 用量稳定低于 Go 栈。**
新进程直接 SSE、先 burst 后 SSE、HTTP/1.1、HTTP/2、并发1/8，两批反序执行均保持此方向。
这里复现的是Linux进程CPU计数信号；独立profile只覆盖了少部分SSE CPU，主要差额尚未归因。
首事件与事件间隔没有出现相同幅度的改善。采样缺口与热点证据见 [CPU.md](CPU.md)。
这是无损同宿主 Linux 真 TUN 实验，不是真实 AI provider、国内网络或原生 Tono 验收。

## CPU 原值：不是扣除空闲后的展示值

单位为每个约30s窗口内**客户端进程累计 CPU ms**，单元格“批1 / 批2”。
`/proc` 100Hz，10ms量化；0ms意味着未跨计数tick，不意味着绝对零工作。

| 场景 | A Tono Mihomo | B sing-box gVisor | C sing-box Go |
|---|---:|---:|---:|
| 新进程预热后 idle | 10 / 30 | 0 / 0 | 30 / 30 |
| 新进程→H1 c1 SSE | 1110 / 1140 | 190 / 190 | 1100 / 1060 |
| 新进程→H1 c8 SSE | 1590 / 1500 | 380 / 360 | 1620 / 1370 |
| 新进程→H2 c1 SSE | 1100 / 1100 | 210 / 220 | 1180 / 1080 |
| 新进程→H2 c8 SSE | 1190 / 1230 | 350 / 370 | 1260 / 1350 |
| 新进程→B2五组burst→H1 c1 SSE | 1210 / 1180 | 210 / 210 | 1110 / 1110 |

B 对 C，在各 fresh 场景/批次的原始 CPU 低约 **72%–83%**；不是对真实用户电量的推算。
C 的 H1/c8 两批差异约15%，但仍远高于 B；A/C 有重叠，不能宣称两者有稳定胜者。
post-burst 与 fresh 的方向一致，不支持“只是前序 burst 残留造成 B/C SSE 差异”的解释。
只有两批，不拟合置信区间，也不把事件展开以制造更大的独立样本数。

**空闲校正另列，不替换原值。** 校正 = 当前CPU − 同候选/同批idle CPU率×当前测量窗口。
例如 fresh H1/c1 的校正值，A为1099.98/1109.94ms，B为190/190ms，C为1069.93/1029.94ms。
CSV保留全部校正值及原始 before/after tick。有限精度下允许负值，不截为0。

## 首事件、间隔与 RSS

fresh H1/c1 每候选仅2条流，报首事件范围：A 51.568–51.800ms，B 51.302–51.417ms，
C 51.323–51.424ms；**其中50ms是服务端主动生成等待**。不从这些数值反推Reality握手。
fresh H1/c8 每候选16条流，首事件p50 A/B/C为52.114/51.252/51.289ms；全样本范围分别
51.944–52.531 / 50.928–51.595 / 50.918–53.136ms。小样本不报连接p99，不据亚毫秒差异做体验排名。

每条流内部有599个到达间隔：fresh H1/c1的**逐流间隔p95**范围 A 50.444–50.481ms、
B 50.409–50.433ms、C 50.422–50.484ms；H2/c8相应范围为 A 50.506–50.629ms、
B 50.622–50.765ms、C 50.544–50.754ms，没有稳定同向的尾间隔赢家。
[streams.csv](raw/streams.csv) 逐流保留首事件、间隔p50/p95/max、完整性和连接证据。
间隔分位数是同一流内的描述，不是独立请求的统计置信度。server/client offsets起点不同，
不能相减当作精确单向延迟。

客户端RSS为250ms采样最大值：fresh SSE A约39.9–45.3MiB，B约39.6–42.6MiB，
C约38.1–42.1MiB。post-burst A 66.9–68.4MiB、B 47.7–47.9MiB、C 45.5–45.6MiB。
这是工作集观察，不足以判定泄漏或GC原因；CPU profile与后续诊断边界见CPU.md。
server/fixture的CPU及RSS也保留，正常窗口累计CPU最大分别390/430ms；各用不同CPU affinity，
但仍共享同一VM资源。两批cgroup throttling增量均0，guest aggregate steal增加5/13 ticks。
不能据此称为无宿主争用。

## Confirmed repairs

### #269: password label masking left the value exposed

[Issue #269](https://github.com/raydocs/tono/issues/269): both Python and Worker redactors matched only the word `password`. Their prior tests explicitly expected the assigned value to survive. Actual collector upload, job persistence and immediate-failure D1 storage reproduced the leak with synthetic values; no real leaked credential is asserted.

The fix redacts plain/quoted assignments before other substitutions and truncation, removes structured password values, and decodes structured result JSON before sanitization. It keeps the original non-secret `i/o timeout`, `handshake EOF` and `connection reset` context. Existing UUID/email/foreign-IP masking and node-IP allowlisting remain exercised. No new telemetry fields, consent, auth policy or retention were introduced. This is a bounded pattern repair, not a universal secret detector.

The Worker helper moved to [job-redaction](../../services/control-plane/src/ops/job-redaction.ts) because it is shared by job storage and failure intake and the jobs module otherwise exceeded 500 lines. This was a separate structural commit; no budget was increased and no statements/comments were compressed to evade the guard.

### #270: nonzero journal reads became successful evidence

[Issue #270](https://github.com/raydocs/tono/issues/270): both journal handlers rejected only rc124. The real dispatcher posted rc255 SSH failure and rc1 partial journal output as `ok`; the Worker then records `succeeded`, which node acceptance uses as observation evidence.

One regression leases three jobs and supplies rc255, partial rc1, and a successful empty rc0 at the SSH boundary. The original output was `['ok', 'ok', 'ok']`; the corrected output is `['error', 'error', 'ok']`. Nonzero reads retain their exit code and no partial digest is counted as complete. rc124 remains timeout. Posting a handler error still successfully completes the collector pass; upload failures retain their existing nonzero process-exit contract. No network-block, UUID or server-rejection claim is inferred from EOF.

## 2026-10-10 · macOS `--emergency-disarm` 先停 helper 守护进程（R3-O4）
- 归属：ops 任务（[运维计划](../ops/plan-2026-09-11.md)；backlog A13，[amp-backlog-2026-10-10](../ops/amp-backlog-2026-10-10.md)）；macOS 特权 helper 操作员恢复命令。
- 来源：`main` 2453dec5 → 分支 `amp/a13-emergency-disarm-bootout`，[#1504](https://github.com/raydocs/tono/pull/1504)；未合 main。
- 缺陷修复：操作员 `sudo /Library/PrivilegedHelperTools/tono-core-helper --emergency-disarm` 在 KeepAlive 守护进程仍在线时放行，守护进程的看门狗、电源回调或 GUI 请求可能紧接着再写 PF/DNS（两个写入者）。现在该命令先 `launchctl print system/com.raydocs.tono.core-helper`，已加载则 `launchctl bootout`，再轮询直到 launchd 不再有它（最多约 50 × 200 ms；单次 launchctl 30 s 超时），然后才执行原有放行（DNS 恢复、PF disarm、更新证据处理，代码未改）。bootout 失败、超时或守护进程本未加载：在终端报告后照常放行，绝不因此停住。
- 新增/优化：放行完成后守护进程保持停止，终端打印恢复办法（重开 Tono 并批准管理员提示，或 `sudo launchctl bootstrap system /Library/LaunchDaemons/com.raydocs.tono.core-helper.plist`；plist 保留，重启后也会自动启动）。放行未完成（PF 被拒或 DNS 未恢复）时按 `--emergency-reset` 的先例重新 bootstrap 守护进程，让它的启动放行与 DNS 重试接手（[决定 084](../decisions/084-2026-10-10-emergency-disarm-daemon-restart.md)，provisional）。只有 CLI 入口 bootout；守护进程内部的删除检查和 `--emergency-reset` 仍走原路径。无新 socket 请求或特权命令，PF 语义不变。
- 工程与测试：helper 4.52.44 → 4.52.45，`CONTRACT.sha256` 按 `build-core-helper.sh` 清单重算（未加源文件，清单不变）。helper 自测 `runOperatorEmergencyDisarmSelfTest`（在 `--self-test` 内）注入 launchctl：bootout 在第一次放行写入之前；bootout 失败（退出 5）放行仍执行。
- 验证：Linux 上 `sh tooling/scripts/test-core-helper-contract-guard.sh` → `PASS build-core-helper contract guard`；用假 `xcrun` 跑 `build-core-helper.sh`，契约守卫通过并到达编译（退出 73）；`python3 apps/macos/scripts/test_build_source.py` → `Ran 2 tests … OK`。Swift 编译与 helper 自测由托管 macOS CI 执行，本机未执行。
- 候选/发布：仅源码，无新候选。
- 剩余限制：未实机验证（真实 launchd bootout 时序）。`--emergency-reset` 在拒绝删除时回退的 `runEmergencyDisarm` 不先 bootout（该路径本任务未改）。运行中的更新执行器（独立 launchd 任务）若之后 bootstrap 新守护进程，不受本命令约束。
- 续记 2026-10-10（独立复核 FAIL：2 MAJOR + 1 minor 修正，仍为 4.52.45）：每次 launchctl 调用改走 `KillSwitchManager.run`（期限后 SIGTERM、1 s 后 SIGKILL、再 1 s 后放弃，不再无界 `waitUntilExit`），整个 bootout+轮询阶段按 20 s 墙钟总期限计（含杀进程宽限）；重新 bootstrap 同样有界。放行报告成功后，用 `ProtectedDNSManager.verifyRestored()`（无待恢复快照、无服务或活动解析器仍是 127.0.0.1）与 `KillSwitchManager.effectiveStatus()`（Tono PF 阻断不在生效）回读；回读失败视为未完成，重新 bootstrap 守护进程让它重试（更新断开路径可能吞掉 DNS 写失败而仍报 `.released`）。`emergencyRelease()` 未改。只有 launchd 明确的「无此服务」（退出 113）算未加载/已停；print 失败或超时为 unknown，不声称已停，放行未完成时同样重启。自测扩展：launchctl 子进程忽略 SIGTERM 时放行仍在期限内执行；print 超时为 unknown；回读失败触发 bootstrap。

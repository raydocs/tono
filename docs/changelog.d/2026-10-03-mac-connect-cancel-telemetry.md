# 2026-10-03 — macOS records a cancelled connect as `connectCancel`

- Plan: [SHIP_PLAN](../SHIP_PLAN.md) G2 (field diagnosability). Owner 2026-10-03 「按你说的做」 item 7, second PR (server kind: #1365).
- Problem: `AppState+Connect.swift` returned from the connect task's catch on `Task.isCancelled` without recording anything. A second click, Disconnect, Quit, sign-out or an update cancelling the attempt left a bare `connectBegin`; the 10-02 snapshot (257 begins vs 34 oks, no failures) could not separate cancels from crashes.
- Change: `ConnectionTelemetryBuffer.recordConnectCancel(stage:elapsedMs:node:generation:)` records kind `connectCancel` with the stage the attempt stopped at and its elapsed time; it does not call the failure sink, so decision 051's automatic failure report is not sent for a deliberate stop. The connect task keeps its start time in a local because Disconnect resets `connectionStartedAt` before the cancel reaches the catch.
- Verification: one XCTest `testConnectCancelCarriesStageAndElapsedTimeWithoutAFailureNotice` (`ConnectionTelemetryBufferTests`). Red commit pushed first (no `recordConnectCancel` → compile error in the test target), then the fix; ci-gate `macos / build` on both heads recorded in the PR. The MacBook ran only `swiftc -parse`; hosted CI builds and tests. Hardware: a second click during "Starting core" should produce one `connectCancel` row in `connection_events` after the next telemetry window (needs the server kind from #1365 deployed; `needs-hardware`).

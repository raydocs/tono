## 2026-09-30 · macOS 续期令牌的短暂写失败不再延续到退出
- 归属：SHIP_PLAN §2 item 10；macOS M11 账户可靠性。
- 来源：main `08aac566` → 分支 `hunt/sol-r3cfg-refresh-token-durability`；PR [#1008](https://github.com/raydocs/tono/pull/1008)；未合 main。
- 缺陷修复：续期成功但 refresh token 写入钥匙串短暂失败时，后继只在内存里保留，普通请求可继续一天都不重试；退出后若超过旧令牌十分钟恢复窗口，重开会丢失会话。普通鉴权请求现在重试持久化；退出排空已在进行的共享续期，再保存最新内存令牌。
- 新增/优化：无。退出只在原网络清理之后等待账户凭据；语言重开和原生更新仍跳过网络清理，沿用二十秒退出期限，不为保存凭据发起网络请求。
- 工程与测试：KeychainStore 增加默认使用 SecItemUpdate 的窄写入接缝；先写两个 XCTest：健康 bearer 下普通请求修复续期写拒绝、退出等待被取消读者留下的共享续期。使用隔离钥匙串命名空间、假令牌和显式释放的 URLProtocol 答复，不访问真实账户。
- 验证：Linux worktree `git diff --check` 通过；独立只读审查未发现产品正确性问题，退出排空测试改用观察回调保证续期释放前已进入等待。Swift/Xcode 不可用，未编译或执行 XCTest；需 hosted macOS CI，不声称本地红绿结果。
- 候选/发布：仅源码，无新候选。
- 剩余限制：持续钥匙串拒绝、退出期限内未完成续期或写入前突然进程死亡仍可丢失只在内存的令牌。PF、DNS、路由、严格模式及 AI 保护均未改变。

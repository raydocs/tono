## 2026-10-02 · macOS optional DIRECT policy apply waits for a removed exit's switch and is retried after a failure
- Ownership: SHIP_PLAN §2 item 10; macOS App, connected-session policy apply (`REGLATE-MAC-POLICY-REQUEUE`, [#1238](https://github.com/raydocs/tono/issues/1238)).
- Source: baseline `f7279dd9`; branch `fix/mac-optional-policy-requeue-1238`, [#1338](https://github.com/raydocs/tono/pull/1338); not yet merged.
- Defect fix 1: a policy update applies on the live session through `applyOptionalDirectPolicyInBackground`. A catalog that removes the selected exit while that owner is busy only queues its switch (`pendingRemovedCatalogExit`). The owner then read the live selection after its awaits: the removed exit has no endpoint, so the owner armed PF without the exit the Core still dialed, failed to build the document (`invalidNode`), re-armed again without that exit and returned. The session was cut until the queued switch ran, and the accepted policy was dropped. The owner now returns before any arm when a removal is pending and queues itself (`pendingOptionalPolicyReload`); the existing drain order (removal, then policy) runs the switch first.
- Defect fix 2: the owner captures the PF exit endpoints, node list and overlay once, before its first arm, and uses them for both arms and the document. A catalog installed during the arm can no longer make PF and the document disagree; the restore after a failure uses the endpoints that arm admitted, and is skipped when nothing was armed.
- Defect fix 3: an apply that fails before `/core/sync` keeps the session (unchanged) but was never queued again, so a revoked suffix or native-app DIRECT grant stayed live until the next policy revision or Connect. It is now queued again, at most twice per session and policy revision; the error message is shown only after that.
- Kept: the failure path after `/core/sync` (automatic release with the AI hold, strict keeps its block), the queue order, the helper and its version. No PF rule text changes.
- New/optimization: none.
- Engineering/tests: `OptionalPolicyTests.testOptionalPolicyOwnerLeavesPFAloneWhileTheSelectedExitIsRemoved` and `testOptionalPolicyFailureBeforeReplacementIsTriedAgain`, pushed alone first as `50add06b` (red run recorded in the PR).
- Verification: no local `xcodebuild` on the MacBook; hosted macOS CI runs the XCTests.
- Candidate/publication: source only; no new candidate.
- Limits: needs-hardware. The retries are immediate, so a failure that lasts longer than three applies (a full disk, a helper that stays busy) still leaves the old plan in force until the next document or Connect. The survivor switch that follows a removal arms without the removed exit for its own duration, as before. A lost `/core/sync` reply is `MAC-SYNC-REPLY-LOST-DIGEST`, not this change.

## 2026-10-27 · Windows 登录错误改为克制的内联提示（对比图方案 A）
- 归属：G1（客户路径 UI）；Windows 海面外观登录页。
- 来源：分支 `amp/windows-signin-error-notice`，叠在 #1796 上（Stacked on #1796）。用户认为出错时的红色提示不够好看，倾向对比图里的方案 A（内联提示，靠近操作）。
- 新增/优化：
  - 海面外观里，登录失败不再是表单下方卡片里的红字，而是放在输入框（或验证码）和主按钮之间的内联提示：左侧图标，首句加粗作为标题，其余一句用次要色；「详情」（尝试过的线路、复制诊断）收在提示里，重试就是紧挨着的主按钮。
  - 严重程度不只靠颜色：可重试的失败是琥珀色「!」圆圈图标，账号层面的答复（套餐到期、流量用完、未开通套餐）是安静的「i」图标和强调色；两者都有加粗首句。对比度（#111018 面板上）：琥珀 13.1:1，强调色 13.8:1，次要文字 9.1:1。
  - 输入框和验证码框的 `aria-describedby` 指向这条提示；提示文字仍在 `role="alert"` 里，首句与其余句之间保留原有空白，读屏读出的就是原文。键盘顺序与视觉一致：邮箱 → 详情 → 发送验证码 → 隐私说明。入场动画遵守减少动态效果。
  - 暂停/到期页里「退出登录」失败的提示同样改用内联提示（新外观）。
  - 新增图标 `alertCircle`、`info`。原外观（非海面）保持不变。
- 未做：没有新增支持渠道；恢复操作只有已有的重试、换邮箱、复制诊断。
- 工程与测试：`login.test.tsx` 新增 1 个 `it`（失败提示在表单里、主按钮之前，被输入框 `aria-describedby` 引用，首句加粗、有图标、带详情；在旧 login.tsx 上为断言红）；已有用例改为逐个解析 `aria-describedby` 里的多个 id。
- 验证（Linux orb）：Windows 前端完整 vitest 61 文件 451 用例通过；tsc、eslint 通过；预览壳截图：860×540 中文连不上服务器、860×540 英文展开详情、860×540 英文验证码被拒、920×600 中文套餐到期（info）、860×540 中文邮箱格式无效、700 宽卡片布局；agent-browser 键盘 Tab 顺序检查。
- 剩余限制：未在 Windows 真机上看（DPI、YaHei UI、WebView2）；未用 NVDA/讲述人实测，只检查了 DOM 和 ARIA；退出登录失败的提示预览壳无法模拟，未截图。

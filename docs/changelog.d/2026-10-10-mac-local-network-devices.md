## 2026-10-10 · macOS：连接中私网放行收紧，新增「允许局域网设备」开关（默认关）
- 归属：ops（[docs/ops/plan-2026-09-11.md](../ops/plan-2026-09-11.md)），backlog A29，finding D7，决策 079 D3-A；macOS App 设置页 + 特权 helper PF 渲染。
- 来源：基线 origin/main `d12e2f9f` → 分支 `amp/a29-lan-devices-toggle`，[#1506](https://github.com/raydocs/tono/pull/1506)；未合 main。
- 缺陷修复：D7。连接中（有隧道）PF anchor 对私网、链路本地、ULA 和 IPv6 组播任意端口、任意用户放行（`tono-lan`、`tono-linklocal`），另放行局域网发现组播（`tono-multicast`、`tono-ssdp`）。改后默认关：这 8 条放行不再渲染，私网只剩 mDNS（UDP 5353 到 `224.0.0.251` / `ff02::fb`）；IGMP、Continuity 网卡、DHCP 广播、NDP 和所有阻断规则（含 #348 的 `tono-lan-dns`）不变。开关打开时渲染的规则与 helper 4.52.44 逐字相同。断开、bootstrap、武装未连接、紧急状态的规则不变（这些规则本来只在有隧道时渲染）。
- 新增/优化：设置页「通用」（经典外观为「偏好设置」）加一行开关「允许局域网设备」/ "Allow local network devices"，沿用现有 `SettingToggleRow` 与说明文案样式，zh/en 文案进 `Localizable.xcstrings`。值存 `AppProfile.defaults` 的 `allowLocalNetworkDevices`；每次武装时读取，只在开时给 arm 请求加 `allowLocalNetworkDevices: true`。连接中切换时置位已有的 heal 重申标志，健康检查（约 5 秒）用同一路径重新武装，不需重连。选择细节与代价见[决策 085](../decisions/085-2026-10-10-macos-local-network-devices-setting.md)。
- 工程与测试：helper 4.52.44 → 4.52.45，`CONTRACT.sha256` 同步；arm 字段白名单加 `allowLocalNetworkDevices`（缺省为关，非布尔拒绝）；`KillSwitchState` 加非持久字段，`loadState`/紧急状态为关，`restorableState` 保留。helper 自测（`--self-test`，CI 以 root 跑并做 `pfctl -nf`）加两条：开时整套规则与 main 逐行相同（`localNetworkOnMatchesMain`）；关时等于该规则去掉恰好 8 条放行，且仍指向私网/组播/广播的放行只剩 IGMP、4 条 mDNS 和 DHCP 广播（`localNetworkOffKeepsOnlyMDNS`）。渲染器只编进 helper，不在 XCTest 目标里，所以这两条按 helper 自测写。一个 XCTest `LocalNetworkDevicesArmFieldTests`：未设置/关时 arm 请求不带字段，开时只带 `true`。既有自测的有隧道样例改为开，保持原有覆盖（含内核加载）。
- 验证：Linux：`sh tooling/scripts/test-core-helper-contract-guard.sh` → `PASS build-core-helper contract guard`；`python3 apps/macos/scripts/test_build_source.py` → `Ran 2 tests … OK`；自写脚本核对开时期望规则的每条静态行都按顺序出现在 `KillSwitchPF.swift`。Swift 编译、XCTest、helper 自测与 PF 解析由托管 macOS CI 执行，本机未执行。
- 候选/发布：仅源码，无新候选。
- 剩余限制：未实机验证。关时代价（决策 085）：路由器页面、打印机、NAS、投屏目标、局域网对端连接中不可达（mDNS 仍能列出它们）；IPv4 单播 DHCP 续租退回广播重绑定；DHCPv6、MLD 被丢弃；与 Tono 并行的其他 VPN 的私网目的地被阻断。Windows 规则 I（决策 048）仍在连接中放行私网且无开关，D3-A「和 Windows 对齐」的前提已过时：本改动后 macOS 关时比 Windows 严，Windows 开关另起任务。与 #1504（A13）同为 4.52.45，后合者按 AGENTS 取 main + 0.0.1。
- 续记 2026-10-10（独立复核 @660a2d37：1 MAJOR + 1 minor，一轮修正）：F1 丢失更新——原先设置页置位共享的 heal 重申标志，进行中的旧 arm 完成后无条件清掉它，PF 可能停在开而界面显示关。改为：每次 arm 只读一次设置并随请求发送，helper 确认提交后记录 `KillSwitchService.appliedLocalNetworkDevices`；失败、结果未知、heal 或保护被释放时置为未知；健康检查（约 5 秒）只要已提交值与设置不同或未知就重新武装（arm 由 `PrivilegedRuntimeCoordinator` 串行，最后确认的值即 helper 持有的值）。设置页只存值。新增 XCTest `testToggleDuringAnInFlightArmIsReappliedByTheNextHealthCheck`（假 arm 在途中把设置改为关，最终已提交值为关）。F2——helper 只接受真正的 JSON 布尔（`CFBoolean`），`1`/`0`/字符串/null 拒绝；新增 helper 自测 `runLocalNetworkDevicesFieldSelfTest`（序列化 JSON）。另：关时规则集的 `pfctl -nf` 解析并入既有 `pfParses`，无 root 时与开时一样大声跳过，不再静默算通过。helper 仍为 4.52.45，`CONTRACT.sha256` 同步。
- 续记 2026-10-10（复核 @b023af26：2 MAJOR，第二轮修正）：R1——关时局域网仍可经本机代理/Core 到达：sing-box 文档对私网 DIRECT，且 `tono-bundle` 允许 root 在 80/443/8000/8080 到任意 IPv4。改为：关时 sing-box 在所有直连规则前拒绝 `10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`fe80::/10`、`fc00::/7`（`OverlayConfig.allowLocalNetworkDevices`，生成文档时读取设置，缺省为关）；PF 在 bundle 放行前加 `tono-bundle-local`，丢弃 root 在这些端口到上述 IPv4 段及 `100.64/10`、`224/4`、广播的流量。开时两边都与 main 相同。Core 文档与 PF 不一致时：Core 关 PF 开更严，Core 开 PF 关由 PF 挡住。XCTest `testLocalNetworkDevicesOffRejectsLocalRangesBeforeAnyDirectRoute`；helper 自测的关/开规则集加上 bundle 放行的两种情形（逐行相同），关+bundle 规则集进 `pfctl -nf` 解析；既有 `testContinuityLocalBypass…` 显式设为开。R2——设置变更触发的重新武装在加载后失败会 `releaseInstalledBlock` 放开保护：改为对同一会话的重新武装（磁盘上已武装、相同非空隧道、本进程已提交过规则）加载后失败时保留已装规则与意图并上报错误，新会话首次武装仍按原策略；helper 自测 `runLiveSessionReArmKeepsBlockSelfTest`（注入加载后失败：锚点与意图保留；新会话仍释放）。helper 仍为 4.52.45，`CONTRACT.sha256` 同步。

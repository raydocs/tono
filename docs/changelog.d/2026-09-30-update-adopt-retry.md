## 2026-09-30 · 同一次进程里重试恢复不再自动再连
- 归属：[SHIP_PLAN](../SHIP_PLAN.md) G1。Windows 更新恢复。不改 WFP、DNS、路由或 TUN。
- 来源：`main` `ee6e028e` 上的 `cursor/update-adopt-retry-a706`（`388a5d80`）；PR #772；未合 main。
- 缺陷修复：第一次 Adopt 确认这是安装器拉起的后继进程后，服务会把记录改绑到这个进程。同一次进程里再恢复（账户错误页的重试）时，服务仍回答「不是重新启动」，采纳状态停在 Allowed，于是再开一次自动连接。现在只有第一次确定的回答可以允许自动连接；之后的回答一律保持住，等用户自己点连接或恢复网络。
- 新增/优化：无。用户自己的连接和恢复网络不受影响。
- 工程与测试：`update.rs` 一条状态机回归。
- 验证：本机 rustc 1.83 编不了该工程。状态转移用同样的 match 复现：第一次 `Some(false)` 得到 Allowed，第二次仍是 Allowed。`cargo test` 未跑，交给 hosted CI。
- 候选/发布：仅源码，无新包。
- 剩余限制：未在 Windows 上走一遍更新中途重试。不确定的第一次回答之后再来一次确定回答，仍然不自动连接，这是原有更严的规则。

## 2026-09-30 · 客户邮箱里的冒号不再把运维列表下一页打成 500
- 归属：运维 API 分页。不进 0.0.74 客户包。
- 来源：`main` `ee6e028e` 上的 `cursor/ops-cursor-colon-a706`（`29133a4e`）；PR #770；未合 main。
- 缺陷修复：客户列表用邮箱当排序键。`encodeCursor` 见到 `:` 就抛 500，而 `a:b@example.com` 是合法邮箱。分页到这一行时整页接口 500。游标两边先做百分号编码再拼接，旧游标（没有 `%`）仍能解开。
- 新增/优化：无。
- 工程与测试：`ops-http.test.ts` 一条往返，并核对一条旧格式游标。
- 验证：`npx vitest run test/ops-http.test.ts`，38 passed。修复前该往返抛出 `Invalid cursor parts`（500）。
- 候选/发布：仅源码，无新包。
- 剩余限制：排序键或 id 里若已有非法的 `%` 序列，下一页会 400 而不是解开。未见这样的节点名或邮箱。

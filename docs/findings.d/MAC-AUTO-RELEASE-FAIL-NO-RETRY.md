2026-10-12 续记：PR #1592 按所有者决定在四轮独立 Codex 审查（第 1–3 轮 high，第 4 轮 xhigh）后关闭，分支 `claude/wifi-switch-mac-auto-release-retry` 保留。四轮都成立的不变量：先还原 Protected DNS 再解除 PF（`disarming = releaseKillSwitch && coreStopped && protectedDNSRestored`）、用户主动释放语义不变、A29 保护故障与严格模式不动、不假报「已放开」、保留 AI hold；第 2 轮起无管理员授权弹窗循环。未解决的根本问题：App 无法区分「自己写 DNS/PF 引起的系统网络通知」和「网络真实恢复的通知」——20 秒冷却、3 秒回声窗口、按上行快照比较三种过滤都会丢掉最后一次真实恢复事件（同一 Wi‑Fi、地址网关不变的恢复被判为回声）；入睡取消重试句柄后，拆线仍在进行时到达的唤醒无人认领；读回后刷新基线会吸收尚未分类的真实变化。未尝试的方向：按通知来源区分——只改了 `Setup:/Network/Service/<id>/DNS` 的通知是自己的写入，改了 `State:/Network/Global/IPv4` 或链路键的才是真实变化。在此之前，恢复路径仍是用户点「恢复正常网络」（#1569，已合 main）。

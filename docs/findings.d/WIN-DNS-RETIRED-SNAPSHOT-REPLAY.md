Combination review of #769/#985/#987 on main `7f382af7`: `dns/mod.rs:2852` accepts proven restoration despite a locked adapter snapshot, but `enable_unlocked` loads that file as current originals and `merge_snapshot` keeps its old same-GUID values. `engine::apply_snapshot` later writes those old values back. #985 already records retirement for DoH captures; the adapter snapshot lacked equivalent evidence. A normal offline DNS change is therefore lost, and an obsolete private resolver can stop answering on the next network. P2 conservatively accounts for the deletion fault plus subsequent configuration change; no whole-machine native outage is claimed.

A digest-bound retirement record now distinguishes inert retained originals from a live recovery obligation. A later restore checks snapshotless Tono-resolver safety and NRPT/DoH cleanup without replaying retired adapters. An explicit enable captures current originals, persists its new pending snapshot, then clears retirement before any protected mutation. A stale record cannot waive a different snapshot's restore proof. Retirement persistence is bounded and best effort after committed restoration; it cannot intentionally refuse release. Strict WFP and selective AI-layer behavior are unchanged.

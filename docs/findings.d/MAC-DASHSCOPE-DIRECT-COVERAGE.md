| MAC-DASHSCOPE-DIRECT-COVERAGE | Dedicated DashScope/Qwen API namespaces fall through Alibaba DIRECT and are absent from both recovery AI holds | in-PR | [#1050](https://github.com/raydocs/tono/issues/1050); [#1084](https://github.com/raydocs/tono/pull/1084) | 高·已确认（P1） | Linux signed-policy, Rust emitters and recovery-module regressions failed before/passed after; Swift/native PF/WFP/DNS await CI and device acceptance. Older clients and arbitrary raw-IP identification remain outside this fix. |

Continues the finding recorded in [#1016](https://github.com/raydocs/tono/pull/1016), rather than reporting a second bug. Baseline `7f382af7`: `apps/macos/Tono/Core/ConfigPipeline.swift:114` includes `aliyuncs.com` as product DIRECT; its assistant list, Windows `config.rs:232`, and both selective recovery lists omit the dedicated model API namespaces. macOS `Configuration/ConfigPipeline+Runtime.swift:694` and `+SingBoxProduct.swift:178`, plus Windows `sing_box/runtime.rs:274`, emit domain protection only with a residential hop. Ordinary hostname-bearing curl/browser requests therefore reach the Alibaba exception; macOS also selects China DIRECT DNS for these names.

The [official Alibaba Model Studio base-URL documentation](https://www.alibabacloud.com/help/en/model-studio/base-url) identifies dedicated DashScope regional/coding endpoints and Model Studio workspace/trial/token-plan namespaces. Four suffix families cover them: `dashscope.aliyuncs.com`, `dashscope-intl.aliyuncs.com`, `dashscope-us.aliyuncs.com`, and `maas.aliyuncs.com`. General object storage and the rest of Alibaba Cloud stay available.

Atomic correction: classify those four families as assistant traffic in every validator and emitter, emit protected TCP before Alibaba DIRECT even without a home hop, reject API UDP before macOS DIRECT, and prefer protected DNS before the broad Alibaba DNS rule. A terminal API-only DNS reject prevents failed primary/backup evaluations from falling through to China DIRECT. Both recovery lists add the same four narrow suffixes. Only `aliyuncs.com` overlapping one of these evaluated-first children is admitted; protected exacts/descendants and all other parent overlaps remain rejected. No wire schema, signature context, policy publication, broad IP block, strict kill-switch rule or release ordering changed. Existing signed broad-parent bytes remain valid; a stored policy explicitly directing an API would be refused.

Evidence: the new control-plane signed-policy integration failed with `domains/dashscope.aliyuncs.com: expected 200 to be 400`; all three new tono-core validator/Mihomo/sing-box regressions failed; the production Windows recovery-module test failed on missing `dashscope.aliyuncs.com`. After the fix, the full control-plane suite passed 975 tests, tono-core passed 347, and the portable production recovery module passed 5. Swift tests are written for admission, Mihomo route/DNS precedence, sing-box route/DNS precedence, and helper recovery coverage, but were not executed on Linux.

依据：`AccountSession.enterEntitlementBlock` 和 `fail(_:signsOutOnUnauthorized:)` 都调用 `descriptorConsumer(nil)`，到 `AppState.acceptTonoTransport(nil)` 里执行 `disconnectAndWait(releaseKillSwitch: false)`：Core 停止，PF 收到只剩引导放行，`isProtectionBlocked` 置真，不安排重连（要等用户续费后点 Check again 或重新登录）。helper 空闲循环 `SocketServer.observeCoreForWatchdog` 在 Core 连续 3 次（间隔 10 秒）不在时释放遗留的 Kill Switch 并恢复 DNS。App 端只有 `applicationDidBecomeActive` 调 `reconcileExternalProtectionState()`，所以释放之后 `AccountBlockedView` / 登录页的 `GateProtectionSection` 和菜单栏仍显示拦截中并给出 Restore internet，而网络其实已通。与 [MAC-PAUSE-WATCHDOG-STALE-BLOCK](MAC-PAUSE-WATCHDOG-STALE-BLOCK.md) 同类，决定 044 没有覆盖这条路径：H17-AUTH-MAC（#516）规定被拒的会话不由 App 释放 PF/DNS，所以这里不改成立即释放，只把读回补上。2026-10-02 读代码发现，没有实机复现。

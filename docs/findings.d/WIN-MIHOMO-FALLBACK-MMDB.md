| WIN-MIHOMO-FALLBACK-MMDB | #1121's `dns.fallback` enables mihomo's default GeoIP fallback filter, so the Windows mihomo Core must download `Country.mmdb` before the tunnel exists and refuses its config when that fails | in-PR | #1221 | 中·已确认（P1，mihomo `-t` reproduction） | Real Windows mihomo connect not run; sing-box path unaffected |

Trigger: any Windows mihomo start (explicit mihomo record, or sing-box binary missing before arm) after #1121. `apps/windows/crates/tono-core/src/config.rs` emitted `fallback` without `fallback-filter`; mihomo's default is `geoip: true, geoip-code: CN`, and its DNS parse calls the GeoIP loader, which downloads the MMDB when it is absent. The Windows payload deliberately ships no MMDB (`apps/windows/app/scripts/prebuild.mjs`). Under the bootstrap WFP arm the download cannot reach GitHub, so the config is refused and Connect fails; StartClash failure then releases with the AI hold (no network loss). Reproduced with the pinned adaptive mihomo `-t`: fails with the #1121 block, passes with `fallback-filter.geoip: false`. Without the fix the default filter would also send every non-CN answer to the backup server, which #1121 meant to avoid.

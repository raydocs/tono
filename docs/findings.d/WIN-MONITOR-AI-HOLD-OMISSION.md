On baseline `2a7d73d7`, an ordinary exit outage fails the periodic TUN checks and in-place proof. `connection/monitor.rs:1391` calls `release_explicit`; `disconnect.rs:69` requests `apply_narrow=false`, and Service `disarm_unlocked(false)` removes the secondary AI hold. The automatic health path now requests the existing applying-narrow release. The same shared predicate still excludes strict protection and policy rebuilds. Explicit user release retains its existing behavior.

One regression exercises the production dispatch boundary: general traffic is released with the AI-hold bit retained; strict/policy paths dispatch nothing; a release refusal propagates. An extracted-source Linux harness using the real `tono-core` predicate failed with the baseline-equivalent plain-release bit and passed with the fix. This is dispatch evidence, not a native network test. No deploy, publication or real-machine network operation.

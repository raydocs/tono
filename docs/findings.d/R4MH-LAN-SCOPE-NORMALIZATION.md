Baseline `c6c08737`: `KillSwitchManager.swift:881` reads `pfctl -sr`, but `KillSwitchPF.swift:82–94` accepts only `on { ... }` on the first labeled line. Native rules use one interface per rule: Apple's [PF rule ABI](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/net/pfvar.h#L673-L689) has one `ifname`, and upstream [pfctl's printer](https://github.com/openbsd/src/blob/65032adb49373e6e9af5a1ac699f167d028a4afb/sbin/pfctl/pfctl_parser.c#L858-L862) prints `on %s`. The scalar output is misclassified as unscoped `[]`, suppressing refresh at `KillSwitchPF.swift:101`. New physical NIC LAN DNS/DoT still matches the unscoped LAN pass behind the old blocks. Public-address connections still face the catch-all; severity remains P2 as in #894.

The parser now aggregates all labeled scalar/list scopes. Any unscoped block keeps the global-block semantics. Refresh widens only existing managed DNS block lines after exact pass-baseline confirmation; it preserves session DIRECT/reviewed-bundle passes and keeps states. Re-rendering persisted recovery state would omit those transient permissions (`KillSwitchManager.swift:1204–1207`), so that latent permission-loss path is removed as part of making refresh reachable. Withheld/unconfirmed sources are not reconstructed.

Regressions cover expanded multi-rule output, unchanged non-DNS lines/session permits, refused withheld/unknown sources, and the existing lifecycle anchor's actual `pfctl -sr` output. Swift/native execution is unavailable in the Linux hunt VM; no executed native red/green result is claimed.

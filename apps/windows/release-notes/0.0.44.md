# Tono 0.0.44

This build fixes the connection and server-switch races that could leave the
selected server, the running tunnel, and Windows protection out of agreement.

- Only one live server switch may update the selector and Windows Filtering
  Platform at a time. Rapidly choosing two servers no longer lets two switch
  operations roll each other back; a second choice asks you to retry after the
  first one settles.
- A confirmed failure of the WFP kill switch or protected DNS now forces a
  protected repair. A successful HTTPS request can no longer make Tono report
  Connected while the fail-closed boundary itself is unhealthy.
- Connection and control-plane pin monitors keep running after an in-place
  network recovery. A later dead exit is detected instead of remaining shown as
  Connected for the rest of the session.
- Automatic reconnect now has a finite retry budget. A deterministic failure
  no longer retries every thirty seconds forever or repeatedly asks for
  administrator approval.
- Choosing another server or pressing Retry now re-arms a spent reconnect
  budget, and failures use customer-readable diagnostics instead of internal
  probe markers.
- Service repair remains available even when automatic reconnect has stopped,
  so a machine cannot be left protected but with no recovery action.

The installer is signed for Tono's updater but does not carry an Authenticode
publisher certificate, so Windows SmartScreen may warn on a first install.

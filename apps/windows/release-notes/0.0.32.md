# Tono 0.0.32

- Turning protection off now stays off. A network change arriving while Tono was releasing — a Wi-Fi hop, a VPN adapter appearing, waking from sleep — could re-arm the kill switch after the release finished, so the machine went back to fail-closed seconds after the user asked for it to stop. Tono no longer treats a tunnel that is in the middle of shutting down as a live one.
- **Retry Now** retries now. It scheduled the retry against the backoff timer instead of running it, so on a slow first attempt the button did nothing visible and the user pressed it again. A sign-in problem also used to latch the button off until the app was restarted; it now clears at the start of every attempt.
- DNS is restored on the adapters Tono actually changed. The restore selected adapters by a test that did not match the one used to record them, so on some machines an adapter kept pointing at Tono's resolver after disconnecting and the machine had no working DNS. Tono now proves each adapter reads back as its own before deciding.
- Setting up automatic start no longer hangs. Tono waited for the Windows task scheduler to exit while never reading what it printed; on a machine where that output was large the pipe filled and both sides waited forever, which showed up as a frozen window during setup.
- Emergency disarm no longer races the service it is disarming. It could run while the service still held the filter engine, leaving the machine armed after the one command that exists to unarm it.
- A malformed request can no longer take the privileged service down. The service refuses an impossible content length instead of aborting, which used to leave the kill switch armed with nothing running to release it.
- A failed upgrade no longer makes the app permanently un-upgradeable. If a replacement rolled back and the old service was slow to answer, recovery copies were left on disk and every later installer run refused before doing anything — including the one the error message told the user to run. Those copies are now cleared once the installed files are proven to be the old ones, uninstalling clears them too, and the message says something that works.
- Sending diagnostics works on a PC whose folder names are not English. A data directory containing Chinese characters made the button spin for ever and never report anything — the request was destroyed part-way through and no answer ever came back. That button is the support channel meant to still work when the kill switch has blocked everything else, so on an affected PC the one way out was the one that was broken.
- **Network Log Upload** can be turned off. The setting existed on the Mac and had no control on Windows, so the upload could be started but not stopped. While it is on, Tono uploads its own log — the hostnames you connected to, the process that opened each connection, and which rule and route it matched — to Tono support. Credentials, URL queries and page content are removed before anything is written, and TLS bodies are never observed. Turning it off stops the upload and nothing from the log leaves your PC.
- Messages that told you to reboot no longer say so when a reboot does not help. Three of them described a barrier that survives restarting, which sent people through a reboot that could not have changed anything.
- WeChat is recognised by its Tencent code signature, not by process name alone. A renamed helper inside an official WeChat install now stays on the direct path with the rest of the app, while a Tencent-signed QQ install and a user-made folder that merely claims the WeChat name do not inherit the whole-folder grant — a WeChat copied somewhere of your own is still permitted, as that exact program rather than as a directory.
- Claude's home route no longer carries IPv6 rules. The tunnel runs with IPv6 off, so those rules could never match anything; they only made the rule table longer. The connect log now also records whether a home route was actually available, instead of leaving it unsaid when Claude went out through the ordinary exit.

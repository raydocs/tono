# Tono 0.0.83 — customer manual-test RC

Manual-install test candidate that replaces the 0.0.82 RC, not Windows stable acceptance or an auto-update rollout. Supports x64 Windows 10 22H2 / Windows 11.

New since 0.0.82:

- **Fixed: sign-in could fail with "cannot reach any relay"** (#1836). The relay list is now two addresses, Westwood on its new IP and Mesa; the blocked Westwood address and the Arosscloud relay are gone. Without a tunnel Tono reaches the control plane only through the relays. The firewall rule set for the relays is versioned anew, so the Service replaces the old rules when it starts.
- Everything in 0.0.82 is kept.

## Install and required tests

Verify the published SHA-256 first. In the old Tono choose Restore, confirm ordinary browsing works, quit with the tray, then run the installer as administrator in the fixed Program Files location; do not use the protected in-app update for this test. 0.0.32–0.0.34 cannot be overwritten directly: after confirming restore, uninstall normally, restart, and install this candidate. If restore, uninstall or an installed-file check fails, stop and contact support.

On a network where the old build said it could not reach a relay, sign out and sign in with Tono not connected and confirm sign-in succeeds; after connecting, confirm the firewall still blocks traffic around the tunnel. Then repeat the 0.0.82 checks. Record the system, old version and candidate hash.

## Known limits

- Sign-in without a tunnel uses only the two relays; a network that reaches neither still cannot sign in. Older installs keep the blocked address, so such a customer needs this build installed by hand or another network for the first sign-in.
- The 0.0.82 limits still apply: the pipeline uses the Tauri update signature, not an Authenticode publisher certificate (SmartScreen may warn); anti-leak rules not measured on a real PC; G1–G3, real WFP/DNS fault behaviour and upgrade/rollback are not accepted.

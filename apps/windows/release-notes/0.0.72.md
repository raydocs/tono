# Tono Windows 0.0.72

Release candidate prepared from the reviewed September 5 integration main.
Includes connection recovery, diagnostics and update handoff improvements.
The matching macOS candidate is 0.0.72 build 72. This is not a claim that
either candidate has passed signing, device acceptance or publication.

## Known limitations

- [#26](https://github.com/raydocs/tono/issues/26): the complete protected
  update journal lifecycle is not yet proven. Do not treat the handoff changes
  as end-to-end upgrade recovery certification.
- [#17](https://github.com/raydocs/tono/issues/17): installed-device upgrades,
  browser Secure DNS changes and real residential traffic replay still need
  authorized hardware/account acceptance. CI is not real-device evidence.
- [#41](https://github.com/raydocs/tono/issues/41): same-main Services CI
  dispatch was blocked by Actions permissions; earlier CI is not equivalent.
- [#4](https://github.com/raydocs/tono/issues/4) and
  [#5](https://github.com/raydocs/tono/issues/5): metering cutover and counter
  generation limitations remain; this desktop release performs no migration.
- [#12](https://github.com/raydocs/tono/issues/12): CI path-filter coverage
  remains incomplete.
- The existing Windows pipeline signs updater payloads, not Authenticode
  publisher identity. SmartScreen warnings may occur. Signing status must be
  checked on actual artifacts, not inferred from these notes.

Publication and update-channel promotion are separate gated operations.

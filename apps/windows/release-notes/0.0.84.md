# Tono 0.0.84 — customer manual-test RC

Manual-install test candidate that replaces the 0.0.83 RC, not Windows stable acceptance or an automatic-update rollout. Supports x64 Windows 10 22H2 / Windows 11.

New since 0.0.83:

- **Fixed: sign-in still failed on a network that resets the TLS name `api.afk.ccwu.cc`** (#1838, #1839). Over the relays Tono now dials the control plane as `static.bicon.dev`, a name served by the same API and admitted by both relays, including in the pre-login network check. Only the relay path changes; a running tunnel, a pinned address and the update download keep their hosts. The firewall rule set is unchanged.
- Everything in 0.0.83 is kept.

## Install and required tests

Verify the published SHA-256 first. In the old Tono choose Restore, confirm ordinary browsing works, quit including the tray, then run the installer as administrator in the fixed Program Files location; do not use the protected in-app update for this test. 0.0.32–0.0.34 cannot be installed over: after Restore, uninstall normally, restart and install this candidate. If Restore, uninstall or the installed check fails, stop and contact support.

On the network where 0.0.83 said it could not reach a relay, sign out and sign in again with Tono not connected and confirm sign-in succeeds; after connecting, confirm the firewall still blocks traffic that bypasses the tunnel. Then repeat the 0.0.83 checks. Record the system, old version and candidate hash.

## Known limits

- Without a tunnel, sign-in still uses the two relays only. A network that also blocks `static.bicon.dev` would need another name; older installs keep the old name, so such a customer needs this build installed by hand or another network for the first sign-in.
- The update check and download still use `releases.afk.ccwu.cc`.
- The limits of 0.0.83 still apply: the pipeline uses a Tauri update signature, not an Authenticode publisher certificate, so SmartScreen may warn; anti-leak rules, G1–G3, real WFP/DNS faults and upgrade/rollback are not accepted.

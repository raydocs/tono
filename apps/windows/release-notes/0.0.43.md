# Tono 0.0.43

This build comes out of a real incident: when the Tono service was not running,
the app said only "protected, not connected" and every diagnostic field read
"unknown", so there was nothing to act on. Connection and routing behaviour is
unchanged.

- Tono checks at startup whether its service is running. If it is not, a banner
  says why and offers Repair: one administrator prompt and Tono starts what it
  needs, with no commands to type.
- Installing and repairing now make sure the Windows Base Filtering Engine is
  usable. The Tono service depends on it to start, and "network accelerator"
  utilities routinely switch it off.
- Frequent network changes no longer trigger back-to-back self-checks. Every
  network change Windows reported used to start a full through-the-tunnel
  connectivity check immediately; on a machine whose adapters churn — common
  with "network accelerator" software installed — those checks overlapped and
  piled up. A successful check now stands for a short window.
- When the dashboard cannot read data, the reason is recorded in the diagnostics
  log. This class of failure previously went only to a local file support never
  receives.

If you can reach domestic sites but nothing outside, check the top of the window
for a service banner and press Repair. To do it by hand, in an administrator
PowerShell run `sc.exe config BFE start= auto`, then `sc.exe start BFE`, then
`sc.exe start TonoService`, and connect again.

The installer is unsigned. Windows SmartScreen will warn on a first install.

当前跨平台状态

macOS已发布 · 自动更新

0.0.65 · Build 65

Apple Silicon、macOS 26.3+。Developer ID 签名、公证、装订票据与 Gatekeeper 校验均已通过；Sparkle feed 已指向本版。这是自 Build 62 以来的第一次自动更新，63 与 64 组装后从未发布，内容都并入本版。

  • 保护规则现在逐条带名字。此前 macOS 会把每条精确规则折叠进旁边更宽的那条——写入 66 条、内核只留 13 条、精确的一条不剩，所以 Tono 说不出流量走了哪条路。没有泄漏，只是这份账目此前并不存在
  • 微信按 Apple 签发的签名识别，不再只认 /Applications/WeChat.app；放在别处或名为 微信.app 的副本同样生效。曾有账号 342 条连接全部走隧道，而界面显示国内直连正常
  • 微信主通道走 80 端口，此前被送进受保护出口，从国内绕行美国往返；两份日志显示 82% 和 72% 的连接是这样出去的。现在一律直连，直连失败仍可回落出口
  • 账户有 home 线路时，claude.ai、claude.com、anthropic.com 与 Anthropic 自有网段走住宅跳点；Claude Code 按安装路径识别，桌面端与命令行不会被拆到两个网络
  • 活动页改为按应用展示：本次会话用过网络的每个应用，按流量排序，直连／住宅／隧道各一条
  • 特权 helper 为 3.12.2，首次启动会要求输入一次管理员密码

Windows已发布 · 自动更新

0.0.32 · Stable

x64、NSIS 安装包。已审计的更新通道已推进到本版——此前它停在 0.0.25，中间每一版都发布过却从未推进通道，所以仍在 0.0.25 的用户这一步会跨过六个版本。安装包未附 Authenticode 证书，全新安装时 SmartScreen 仍会告警。

  • 微信的图片、文件和语音能收发完了。直连放行此前只认连接那一刻查到的地址，而微信是边用边找服务器的——之后找到的全被发出去然后静默丢弃，表现就是一直转圈。放行仍有边界：四个端口、只给 Tono 自己的路由引擎、且永不放行内网地址
  • 登录会在同一台服务器上改试备用端口再放弃，能穿过只封 443 的网络
  • 服务繁忙时「断开」和「恢复上网」也能送达。此前建立连接只给 150 毫秒，而同一步里的安全校验却有三秒——保护开着、没有网、而唯一能解除它的按钮没反应
  • 隧道出不去时不再显示「已连接」；关闭保护后不会因换 Wi-Fi 或睡眠唤醒而自行重新武装
  • App 与 Service 必须同版：本版要求服务协议 14，安装器在一次提权事务里同时替换两者

CHANGE ARCHIVE

版本改动备份

2026-08-14

macOS 0.0.65 · Build 65

自 Build 62 以来第一次真正送达用户的更新，同时作为 macOS 的回滚基线：Sparkle 不会安装更低的 build，后续若出问题，应以更高 build 重新发布本份源码，而不是让用户降级。63 与 64 组装后从未发布，内容都在本版。保护规则改为逐条带名，此前内核会把 66 条折叠成 13 条且精确规则一条不剩；微信改按 Apple 签名识别并把 80 端口留在国内直连。

2026-08-14

Windows 0.0.32

修好微信图片与文件一直转圈：直连放行此前只认连接那一刻查到的地址，之后微信自行找到的服务器全被静默丢弃。同日把已审计的更新通道从 0.0.25 推进到 0.0.32——此前通道推进的工作流与其部署环境指定了不同的分支，从 main 触发会显示成功却什么都没做，这就是 0.0.26 至 0.0.31 发布后无人收到的原因。

这两版是基准。之前的每一个构建都已撤下——它们带着这两版修好的缺陷：微信在连接后自行找到的服务器被静默丢弃、Kill Switch 解除后会自行重新武装、隧道明明出不去却仍显示已连接；其中若干版本因为更新通道从未推进，任何客户都不曾拿到过。旧版本的 tag 已一并删除，但源码没有丢失——每个被撤下的构建都已合入主线，仍可按 commit 检出重建。删掉的只是“它仍是一个选项”这层暗示。
